Projects Rework: Mock Board
The old vocabulary is gone. Everything is a project now. A note's project comes from a body tag (#project@research), exactly one per note, and a note with none is simply loose: a normal, permanent state. Auto-tagging only ever picks an existing project or suggests a new one for approval; it never creates one on its own. Three desktop layouts, two phone tile layouts, one inbox-suggestion pattern. Pick one per surface.
Motion note: every transition below (row lift, tile press, suggestion banner rise, approve flash) collapses to an instant state change under prefers-reduced-motion: reduce, so toggle it in your OS to verify live in this file.
Surface A: Desktop
The Vault page becomes Projects
Three layouts for the same page: see all projects, create one, edit its description, rename, delete, drill into its notes, and see everything loose. Each echoes the phone tiles page's tile/panel language without copying it verbatim. Desktop gets room for the description text the phone's semantic matcher actually depends on.

Picking one writes the #project@name tag into the note body; there is no "create new" option here, matching the rule that assignment only ever picks from what exists.

Surface C: Desktop Inbox
A suggested new project waits for approval
When the engine thinks a genuinely new project is warranted, it says so directly on the Inbox row instead of silently inventing one. Approve creates the project and files the note into it; Dismiss leaves the note loose and the destination dropdown available as usual.
