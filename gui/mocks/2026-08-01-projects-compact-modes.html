Projects in compact mode: the project screen, rebuilt around V2

The user drove the composite build, picked V2's reveal-footer action model, and specified exact changes to the project screen. This is that rebuild, one live panel. Every panel is exactly PANEL_W by PANEL_H from gui/src/lib/compactPanel.ts, at true 1:1 scale, no scale transform. The capsule bar above it is unchanged: ALL_TARGETS in gui/src/components/PillMenu/icons.tsx is search, today, vault, settings, inbox, stats, hide, shared by the capsule bar and the minimal radial, and PANEL_W is exactly 7 targets by 44 plus 24 padding. Its Inbox icon was already real and stays real.

A note's project comes from a body tag like #project@research, one project per note, no tag means the note is loose at vault root (a normal state). Both apps group by tag, never by path. Tile mode shows project groupings; rows mode shows individual non-action tags only. Auto-assignment only ever picks an existing project; unsure captures land in the Inbox with two candidates offered as one-click choices; deleting a project never deletes its notes, they go loose.

What the project screen does now

The panel title itself is the editable project-name field: the redundant name field that used to sit in the body is gone, renaming from inside a project happens by editing the title directly. At rest it reads as plain text, no border, no fill; hovering tints it, focusing it turns on a border and background so it is unmistakably a field the moment you touch it. Enter or clicking away commits, Escape reverts. The body now holds only two things: the notes list and the description box.

Layout behavior, the important part. The description box sits directly below the notes list in normal document flow and gets pushed down as notes are added. Once that combined content reaches the bottom bar, the notes list stops growing and starts scrolling on its own, while the description box stays pinned directly above the save and delete row. This is one CSS rule, not a scroll listener: the notes list is a flex item that takes its natural height until the flex container runs out of room, then shrinks and scrolls; the description box never grows, so it never gets pushed off screen. Try both seeded projects below: research has three notes and shows the pushed-down state with room to spare; onboarding-v2 has nine and shows the pinned, scrolling state.

Bottom row. Save is the rectangle on the bottom right, labeled and in the accent fill, the easiest thing on the panel to hit. Delete is a small square icon with no label, sitting quietly to save's left. The description box also carries its own small expand icon; it no longer pushes a separate screen. Clicking it grows the textbox in place to take over the body, the note rows slide out (not a snap-hide) as it grows, and the title stays the project name, still editable, the whole time. Pressing back (the header chevron, or the same icon again) plays the reverse: the textbox shrinks to its pinned size and the notes slide back in. It is a measured two-pane height swap, not a screen transition, and it honors reduced motion the same way everything else here does.

Opening a note. Tapping a note title briefly overlays "Opening in the full note editor" inside the panel, then returns to where you were. That overlay is a stand-in: the compact panel is fixed at 332 by 320, and Second Thought's native note editor is a full document surface with a toolbar, wikilinks and more. It cannot be hosted inline at this size. The real behavior this represents is the same compact-to-full promotion the app already uses elsewhere, not a new mechanism.

Two problems the rules create, flagged rather than quietly designed around.
Hover has no touch equivalent. The tile rename icon only appears on hover, and the title field's own "reads as editable on hover or focus" behavior is the same assumption one level up: a pointer that can hover before it commits. Capsule and minimal compact modes are desktop, mouse-driven overlays, so this is likely fine as designed. It would need a tap-and-hold or an always-visible affordance the moment this UI has to run on anything touch-first.
The hover edit icon collides with A2's own count badge. A2's tile already puts the note count in the top right corner; putting the rename icon there too means two things want the same 16px slot. Resolved by swapping the count for the edit icon on hover, in the same slot, rather than stacking both or shrinking the tile further.

The build

V2's action model, project screen rebuilt to spec

Reveal footer (grows in only in an editing context), A2 two-column tiles sized to fit the panel with no horizontal scroll even on an unbroken 40-character project name, a real segmented toggle for tiles/rows (the same control and motion as capsule Inbox's Inbox/Reminders switch), plus icon in the header, header limited to exactly three icons with no Inbox among them, B-style drill-in with a back chevron, hover-to-rename on the grid crossfading with the note count, editable title field for in-project rename, pinned description over scrolling notes, asymmetric save and delete, an in-place description takeover, and the note-open handoff.

Tile/rows toggle. This was two separate icon buttons; it is now gui/src/components/ui/SegmentedToggle.tsx's own markup, a role="tablist" with one sliding pill behind two role="tab" buttons. The pill's width and step come from lib/segmentedToggle.ts (indicatorWidth/indicatorTransform, n=2 equal segments), its transition is the real 0.2s cubic-bezier(0.16,1,0.3,1), and the segment buttons reuse index.css's .btn-hover utility rather than a bespoke hover style. Switching modes swaps the tile grid or rows list underneath with index.css's own .seg-swap-panel/segSwapIn keyframes (220ms, --menu-travel-ease), directional per lib/segmentedToggle.ts's slideDirection: tiles to rows enters from the right, rows to tiles enters from the left. The pill and buttons are patched in place rather than rebuilt on every toggle, the same way the description takeover is, because a freshly rebuilt pill has no prior position to visibly slide from.

What this locks in

The project screen no longer says the project's name twice. Renaming, describing, saving and deleting all live where they now belong: identity in the title, content in the body, commitment in a bottom row weighted so the safe default (save) is the easy target and the destructive one (delete) is deliberately smaller and quieter. The notes-scroll-under-pinned-description behavior needed no JavaScript layout math, a single flex rule does it. The one open question that stays open on purpose is hover-only discoverability, which is a reasonable bet for a desktop, mouse-driven surface but not a free one.
