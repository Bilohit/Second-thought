Folder import & notes your phone wrote

FR-23 Option C — the last open choice 2026-08-04 · s140

Your folders hold notes written on both peers. The import adds one #project@<name> line to each note in a folder you tick. The question is whether it is allowed to add that line to a note the phone authored.

Checked at source before designing this — the constraint is smaller than it reads:
  • The provenance gate lives inside the enrichment pass only (mobile_sync_agent.py:1459-1466) — a continue that makes the desktop's automatic LLM pass skip phone-authored notes. It is not a global write barrier: nothing blocks, reverts or conflicts with a write from elsewhere.
  • Both peers derive project: from the body by the identical rule (binding contract lock), so after a sync the phone reads the tag and agrees. No ping-pong.
  • The import skips notes that already carry a tag, so running it twice changes nothing. It is idempotent by construction.
  • The line is ordinary body text, one line, visible, and the user can delete it like any other tag they typed.

The exception, written so nothing else can claim it

this is what keeps it from spreading
Recorded in DECISIONS.md §5 as a narrow carve-out, not a softening. A surface may write into a note it did not author only when all three hold:
  1. User-initiated per item — the user selected this specific set, in this session. Never a scheduled or background pass.
  2. Shown before written — the exact count and the affected folders are on screen at the moment of consent.
  3. Idempotent — running it again is a no-op, so it can never oscillate against the other peer.
No enrichment pass, sync pass, or reconcile path can satisfy the first condition, which is what makes this non-transferable. The enrichment gate at mobile_sync_agent.py:1459-1466 is untouched and stays exactly as strict as it is today.
