A note on what "alive" is for. The catalogue is full of ambient star fields, and nearly all of them keep motion going by moving things. The one idea worth stealing is the opposite: the oldest star-field trick is twinkle — brightness varies, position does not. That matters here for a reason beyond taste. Position writes are what keep the layout non-idle, which is what burns the battery and what makes the screen impossible for the accessibility tooling to read. Brightness costs neither.

Positions settle exactly as in 1 and the physics loop stops for good. What continues is brightness only — each star breathes on its own slow phase, never moving. The field holds its shape while still reading as a live sky rather than a screenshot.

On the device this is the cheap half: opacity is one of the properties the native animation driver handles off the JS thread, so it costs no JS frames and writes no layout. Positions are static, so the accessibility tree is dumpable and the layout is idle — alive and idle at the same time, which the current design treats as mutually exclusive. Settles like 1, then stays still — except for the stars whose notes have something to say. A queued note breathes; a conflicted one pulses harder. Everything settled and synced is motionless.

This extends the rule the product already lives by. Colour here is never decoration, only state; this says the same of motion. The sky stops being wallpaper and starts being a read-out — you can tell from across the room whether anything needs you.

Applies to whichever wins: any touch, pinch, or data change re-arms the envelope, so the sky wakes when you use it and settles again a few seconds later. Without that, a settled field would feel broken the first time someone dragged a star. It is not a separate option — it is a requirement of all three.

Reduced motion stays honest. With the OS setting on, there is no drift to decay and no breathing: the field arranges itself and stops. That is already what the code does today, and none of these options change it.

The measured baseline that started this: at 30 nodes with reduced motion off, the maximum per-frame movement is still 0.0375 px at frame 3000 and oscillates indefinitely — it does not trend toward zero. With reduced motion on it reaches zero and stays there from frame 1027.
