The #daily tag — shape, case, and its switch

SP3 Task 10 — your reframing 2026-08-04 · s139
Already settled, not up for a vote: daily notes land in _loose/ · there is no Daily project and none is invented · #daily is a plain descriptive tag, so it flows into the derived tags: frontmatter cache and gets its own row in Tags mode · the switch defaults on.

Three things still have to be decided, and each has a real consequence. Verified at source today: the tag scanner does no case normalization, and the trailing tags: line is a machine-managed region that another pass already rewrites.

2 — Which spelling

the scanner does not case-fold, so these are two different tags
C1 — #dailyrecommended
# 2026-08-04
#daily
Tags mode
#daily31
#capture12
#wikipedia4
  • Matches every other tag in the vault, which is lowercase.
  • Lowercase is what a user hand-types when adding it to an older note.
C2 — #Dailyalternative
# 2026-08-04
#Daily
Tags mode — if anyone ever types the other one
#Daily31
#daily2
#capture12
  • Reads as a proper name, closer to the old Daily project idea.
  • Capitalised is the odd one out next to every other tag.
  • Splits into two rows the moment anyone types the lowercase form — the scanner does not fold case.

3 — The switch

drawn in Settings ▸ Function’s real row idiom
S1 — plain togglerecommended
Auto-describe New Folders
Tag daily notes Adds #daily to each new daily note so they group under one tag.
Reminders Task Scheduler
  • One boolean, one row, nothing to validate.
  • Sits with the other vault-behaviour toggles already on this tab.
  • If you want a different word, you type it into the note yourself.
S2 — toggle + custom namemore surface
Auto-describe New Folders
Tag daily notes Adds this tag to each new daily note.
Daily tag daily
  • Rename it to journal, log, anything.
  • Needs validation — the tag grammar rejects spaces and most punctuation, so it needs an error state and a message.
  • Two controls for one behaviour, and a second row that is meaningless while the toggle is off.
  • Renaming it later does not retag old notes, so the vault ends up with two tags.
The combination I would ship: P1 + C1 + S1. A plain #daily line under the heading, written once as template text, with a single toggle next to the other vault-behaviour switches. It adds one line to a template string, one boolean to config, and one row to a settings tab — and it touches no machine-managed region, so nothing can quietly rewrite it later.
