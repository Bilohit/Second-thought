Where does the #project@Daily tag live in a daily note?

SP3 Task 10 2026-08-04 · s139 decision recorded s127, mechanism verified at source today

You already decided daily notes get a real registered Daily project rather than going loose. Probing it at source today found that decision is necessary but not sufficient: registering Daily in .projects.toml changes nothing on its own. A note’s project is its body tag, so a tagless daily note resolves to None, gets project: [-] in frontmatter, and the next tidy pass moves it out of Daily/ into _loose/.

So the tag has to be in the body, and you can see it. That is the only open question here — everything else is forced by the architecture. Three placements below, current state first.

The tag is the only truthFrontmatter project: and the index column are derived caches of it. No tag means loose, whatever folder the file sits in.
Body is sacred — this is the exceptionThe originating device may author the content it creates. The desktop mints this note and its template; it never edits a note the phone wrote.
One-time, at creation onlyThe template is written once. After that the note is yours, and create_daily_note is find-or-create — it never rewrites an existing body.
Every note stays at depth 1Daily/ is a real directory sibling to any other project, so ../_attachments/ refs survive every move.

- [ ] |

What ships either way

not part of the choice
PieceBehaviour
Daily registry entryCreated on first daily-note creation if absent, the same way Inbox approve registers a new project. Never hardcoded as a category.
Existing daily notesUntouched. create_daily_note is find-or-create; an existing note is returned as-is, body byte-identical. Old tagless daily notes stay tagless and go loose on tidy — the same as today.
project: [Daily] frontmatterFalls out of the tag automatically via serialize_note. Not written by hand.
TidyNow agrees with the folder instead of fighting it: tag Daily → directory Daily/ → no move planned.
Why A is recommended. B and C both put the tag somewhere the user is going to be typing or reading as prose — B into the Log they write down into, C inside the date heading they read as a title. A puts it in the one place that is already machine-adjacent: directly under the title, above the first thing you author. It is also the only one of the three where the tag’s position is stable for the life of the note.
