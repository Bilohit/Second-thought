Two findings from the live smoke run against your actual vault, recorded here so you see them next to the design.
The index's project column is a stale derived cache. Task 11 renamed category to project without re-deriving the values, so /stats and /search?project= currently report personal, work and recipes as projects that do not exist in any registry. Every count those routes return today is describing the deleted taxonomy, not the new one.
project_registry.rebuild_from_vault has zero non-test callers. It was built and never wired to anything. Whichever option wins, the "rebuild from the tags in my vault" recovery path this page will want does not currently exist as a reachable action.
New in v2: the phone-match meter has no defined threshold anywhere in the spec. §3 says the phone "picks the best above a threshold" and §4 says the description is what it embeds, but no number is written down. The three bands drawn below are a placeholder (character count), not a contract. Until a real threshold exists, the meter can only say "more text is better", which is weaker than it looks.

What moved since v1

The toggle is two-way everywhere

Projects (tiles) and tags. The middle "rows" position is gone, so the control means the same thing on the full window, in the capsule and on the phone.

New project is a rail footer

Welded to the bottom of the rail in every state. It never floats above the suggestion or gets pushed around by how many projects you have.

The suggestion is a decision, not a briefing

Name, one fact, three buttons on one line. Create, Rename, and an icon-only dismiss that turns red under the cursor.

Sorting is an instrument

A button that cycles three arrangements, changes its own icon, changes what the right-hand column reports, and moves the rows to where they now belong.
