What "defined" has to mean in code, whichever wins

Desktop sizes are almost entirely inline fontSize: 11 in TSX — 350 of the 358 sizings, only 8 live in index.css, and there is not one Tailwind text class in the repo. So a CSS custom property alone cannot carry this: desktop needs a lib/type.ts export consumed by inline styles, mirrored to --fs-* properties for the 8 CSS sites. Phone extends the existing font.size object in tokens.ts, which already holds three of the names. Both get a sibling test asserting the two ladders are equal, the same way typeface.test.ts now guards --mono/--track — otherwise the vendored copy drifts, which risk 2 in the plan says is asserted by nothing today.

02

How BROWSE pages its projectsphase 3 + 4

Checkpoint question 2 in the program plan. The V2 mock gives the desktop clickable arrows and the pill indicator dots only, and says nothing about the phone. No project pager exists in either app today, so this sets a pattern — but not on blank ground.

Precedent already decided — and it is a different surface

SP3 Task 9 settled the notes-list pager: option C, a range readout with plain prev/next steppers, footer-anchored — "Showing 1–200 of 438" — chosen over numbered pages and over folding prev/next into the head row (gui/mocks/2026-08-03-projects-pager.html). Two rules came with it and bind every option below, so they are not on the ballot: a pager exists iff total > page size, never ≥ — "Page 1 of 1" is banned by name — and under one page there is no pager and no trace of one: no disabled arrows, no dots, no reserved space.

That decision governs a vertical list of hundreds. This one governs a fixed 4×2 grid of project rects whose page count is small and knowable at a glance, on three surfaces with three different pointers. The precedent argues for steppers where there is room for a readout; it says nothing about a 288px pill panel or a thumb.

Whether the editor survives a tab switchphase 3

Checkpoint question 3. In the mock the editor is a window-level slide-over from the right; it closes when you switch to any tab except BROWSE, where it stays open on top. The plan flags this as possibly a mock bug. It reads as deliberate — but the behaviour only pays for itself if BROWSE can put something into the open editor, and no such flow is in Phase 3's scope.

Two that need a yes or no, not a mock

  • Push the three commits? Desktop master is 2 ahead (ca1b58e Phase 1, 9175794 Phase 2), phone main is 1 ahead. All four gates green on a quiet tree. Last session's go was one-time, so the hold is back on.
  • A standalone live round on the typeface, or fold it into Phase 3's? The release exe was built before the swap, so nobody has seen IBM Plex Mono running. A standalone round costs one rebuild and confirms the typeface independently of an IA rewrite; folding it in saves the rebuild but means the first look at the face is also the first look at five new tabs.
